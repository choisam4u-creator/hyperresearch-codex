# 직접 입력 전달 실측 — 2026-09-15

고정 합성 질문 6개에서 파일 전달을 `--inline-inputs`로 바꾸자 전체 연구 토큰은 **1,422,848 → 1,194,955 (16.0% 감소)**였다. 그러나 전체 본문 품질 통과는 **5/6 → 4/6**으로 줄었다. 따라서 이 실험은 관찰된 토큰 절감을 보여주지만, 품질을 유지한 일반적인 효율 향상을 입증하지 않는다. 옵션은 기본 OFF다.

## 비교 조건

동일한 fork 후보 코드에서 파일 전달과 직접 전달을 질문당 한 번씩 교차 순서로 실행했다. Light / lean / facts / 목표 700단어, 동일 원문·질문·역할별 모델·설정을 사용했다. `packet_inputs`, 근거 선택, 분석 재사용, adaptive 경로, 자동 모델 전환은 사용하지 않았다. 차이는 `inline_inputs` 하나다. 검색 없이 고정 원문을 사용했지만 모델이 생성하는 분석·초안·비평은 실행마다 달라질 수 있다.

직접 전달은 writer·draft·critic의 준비된 파일명·본문·출처 wrapper를 프롬프트에 넣고 UTF-8 stdin으로 전달한다. 원문 발췌 상한과 검사·수정 단계는 유지하며, packet 옵션의 digest 삭제는 적용하지 않는다. baseline은 **이 fork의 파일 전달**이며 원본 hyperresearch가 아니다.

## 품질 판정과 검증 범위

사전에 고정한 필수 사실·조건·올바른 유보 기준과 전체 본문을 함께 검토했다. 동일 기준의 보정 예제 6개를 각각 통과한 Terra와 Astra가 시스템 이름·비용을 가린 보고서, 전체 합성 원문, 실제 writer 입력을 해시로 재구성한 처리 메타를 검토했다. 판정 차이는 원문에 근거한 Astra 재판정으로 정리했다. 이는 모델 검토 결과이며 외부 전문가의 정답 인증이 아니다.

평가자의 잘못된 인용·참조와 불완전한 보정 시도도 비용 원장에서 보존한다. 존재하는 보고서 줄의 연속 구간 복원과 동일 출처 참조의 중복 제거만 기계적으로 허용했으며, 등급·사유·오류 판정은 바꾸지 않았다. 소유 보고서에 없는 ID는 거부하고 별도 평가 시도로 기록했다. 누락됐던 실제 writer 메타를 보충하기 전의 평가는 최종 품질 근거에서 제외하고 비용에는 포함했다.

사례당 한 쌍, 합성 자료, Light 경로의 결과다. 일반 웹 검색, Full 결과 품질, 원본 오픈소스 대비 우위, 실제 Windows 모델 실행, 외부 사용자 환경은 검증하지 않았다. 자동 `quality.json`과 전체 본문 판정은 서로 다른 검사이며 자동 완료를 품질 통과로 취급하지 않았다.

## 남은 분모 조건 누락: 패치 단계만 재검증

산림 보고서의 원문 입력과 초기 초안에는 분모 제외 조건이 있었다. 비평이 ‘유연한’이라는 표현을 지적하면서 제안한 문장으로 교체하는 과정에서, 지적 대상이 아닌 분모 조건까지 사라졌다. 따라서 전체 연구를 다시 실행하지 않고 패치 프롬프트에 기존 사실·분모·제외 조건 보존 및 최소 구간 수정 원칙을 추가했다. 특정 정답이나 사례의 숫자는 프롬프트에 넣지 않았다.

F는 원래 패치 입력 4개 파일(14,581바이트), 모델·추론 강도·스키마·파일 전달 방식을 그대로 사용한 **알려진 사례 1건의 패치 재실행**이다. 원래 모델 응답을 실제 수정 게이트에 적용하여 기존 E 보고서와 처리 결과가 바이트 단위로 같음을 먼저 확인했다. 수정 프롬프트의 새 응답도 같은 게이트에 적용했다. 보고서를 사람이 보충하지 않았다.

Terra와 Astra가 전체 원문·같은 정답 기준으로 두 보고서를 독립 평가했고, **양쪽 모두 기존 보고서 실패(필수 내용 4/5), 수정 보고서 통과(5/5)**로 일치했다. 치명적 오류와 미확정 판정은 양쪽 모두 0건이다. 출처와 부합하는 F1/F2 제안은 건너뛰어 원래 조건을 보존하고 F3만 적용했다.
