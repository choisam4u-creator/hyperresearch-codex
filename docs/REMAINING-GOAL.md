# 남은 작업 Goal: 구현과 실측 분리

2026-09-14 요청에 따라 Phase 8–13의 남은 항목 중 로컬에서 구현·검증할 수 있는 다음 네 묶음을 진행했다. 실제 리서치 호출, 외부 검증, Windows 실제 모델 실행은 하지 않는다. 유지보수 대화의 토큰과 리서치 실행 토큰은 별개다.

| 묶음 | 결과 | 아직 입증하지 않은 것 |
|---|---|---|
| 세부 주장과 근거 | 기존 인용 검사 호출에서 세부 주장·지지/반박 인용·조건·한계를 받는 선택 계약, 실제 전달 발췌와 원문 양쪽의 해시·위치 검증 | 모델의 주장 분해 완전성, 의미 판정 정확도 |
| 평가 실행 | 정답 분리 benchmark·독립 판정·통제 비교를 CLI로 연결 | 독립 판정의 정확성, 실제 모델 우위 |
| 전체 토큰 보호 | 입력+출력 합산 중단 기준, 진행 중 입력·출력 예약, 미측정 뒤 중단, 재개 상한 유지 | 호출 내부 토큰의 강제 결제 상한, 실제 절감률 |
| 보고서 형식 | 사실 확인·조건별 비교·근거 분석 형식을 기존 작성 호출에 적용, 검토 요약의 미측정 표시 | 모델의 형식 준수율, 사람의 검토 시간 감소 |

## 사용법

```bash
# 파일 생성·모델 호출 없이 계획만 확인
hpr run "조건을 보존해 두 선택지를 비교하라." --format comparison --total-budget 500000 --max-calls 24 --plan-json

# 중단된 실행의 총 토큰 기준 조정
hpr resume RUN_ID --total-budget 700000
```

`--format brief|facts|comparison|analysis`는 기존 작성·초안·종합 호출의 지시에 형식을 더한다. 기존 필수 절·원 질문·분량·인용 규칙을 유지하고 호출은 추가하지 않는다. 형식은 실행 설정에 저장되며 재개 중 바꾸지 않는다. 실제 결과 형식은 모델 검증이 필요하다.

`--total-budget`은 알려진 입력+출력을 합산하고 캐시를 다시 더하지 않는다. 실패·재시도도 포함한다. 실행 중 예약 입력과 호출당 출력 여유분(`budget.output_reservation`, 기본 4096)을 더해 다음 호출을 허용할지 결정한다. 총 예산을 지정하면 standard에서도 사용량 미측정 뒤 다음 호출을 멈춘다. 이미 진행 중인 호출의 과소 추정·출력 초과는 막지 못하므로 강제 청구 상한이 아니다. 입력 기준 `--budget`과 함께 지정하면 두 기준을 모두 적용한다.

## 세부 의미 검사

작업 공간의 `research/config.json`에서 `verification.semantic: true`를 선택한다. 기본 OFF이며 이 변경은 저장된 실행 설정을 바꾸지 않으므로 새 실행에 적용한다. Full 다듬기 뒤 바뀐 인용까지 검사하려면 `verification.recheck_changed: true`도 설정한다.

새 호출을 더하지 않고 기존 `citecheck` 응답에 세부 주장을 받는다. 주장 문구는 보고서 표본의 정확한 부분 문자열이어야 한다. 근거 문구는 인용된 출처 중 검사에 실제로 보낸 발췌와 원문 모두에 있어야 한다. 없는 출처·위조 인용·중복 판정·잘못된 구조는 미검증으로 처리한다. 지지 근거 없이 supported로 반환해도 통과시키지 않는다. 지지와 반대 근거가 섞인 경우 명확한 지지로 단정하지 않는다.

검사 결과는 `citecheck_semantic.json`과 선택적 `citecheck_changed_semantic.json`에 저장된다. 호환되는 스냅샷의 동일 문장만 `evidence_ledger.json`의 `semantic_atoms`에 연결한다. 바뀐 문장이나 오래된 검사 맥락은 상속하지 않는다. 조건·한계 및 관계는 **모델이 제안한 판정**이다. 정확한 문자열·위치 검증으로 그 판정의 진실성까지 증명할 수 없다. 인용 표본 밖 문장과 무인용 주장은 이 호출의 의미 검사 범위에 포함되지 않는다.

응답이 길어져 출력 토큰이 늘 수 있다. 실제 비교 전에는 기본값으로 켜지 않는다. mock은 의미 판정을 만들지 않고 `insufficient`를 반환하므로 모의 보고서가 검토 필요로 끝나는 것이 정상이다.

## 실제 실측 계획 — 아직 실행하지 않음

첫 실험은 개발 자료 2개 × 모델 배정 2종 = 4회다.

- `fact-ko-01`: “두 고정 사실을 출처별로 짧게 확인하라.”
- `compare-en-01`: “Compare the fixed options without naming a universal winner.”
- 동일 Light 설정·출력 분량·형식·프롬프트·고정 자료·기준 시각을 유지하고 역할별 모델만 변경한다. `standard`와 `economy`는 출처/비평/분량도 달라 그대로 모델 배정 단독 비교로 쓰지 않는다. lean 크기의 같은 설정에 기준 Astra 역할표와 economy 후보 역할표만 각각 적용한다.
- 회당 총 토큰 중단 기준 제안: 500,000, 호출 상한 24, 미측정 중단. 네 번의 기준 합은 2,000,000이며 실제 청구 상한을 보장하지 않는다. 과거 Light 입력 실측 380,000–700,000 범위를 보면 중단될 수 있다. 중단된 실행의 예산을 자동으로 올리거나 재시도하지 않는다.
- 실제 실행 전 질문·네 번의 실행·합산 예산을 사용자에게 확정받는다. 추가 심판 모델 호출은 이 네 번에 포함되지 않으며 자동 실행하지 않는다.
- 생성된 보고서를 독립적으로 판정하고 보고서 SHA에 묶는다. 판정 누락은 unknown으로 둔다. 실패·품질 미달 비용도 포함해 통과 보고서당 입력+출력을 비교한다.
- 개발 설정을 고정한 뒤 보류 8개를 평가한다. 이 단계의 횟수와 예산은 첫 실험 결과를 보고 정한다.

원본 hyperresearch와의 동일 조건 비교, 의미 오류 탐지 목표, 토큰 30% 절감 목표는 여전히 미측정이다. 입력·출력 형식을 줄이거나 쉬운 사례만 골라 목표를 달성했다고 보고하지 않는다.
