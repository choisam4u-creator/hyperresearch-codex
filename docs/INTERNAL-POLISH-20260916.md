# 기존 자료 기반 품질·비용·체험 보완

2026-09-16. 새 연구·평가 모델 호출 없이 저장된 실패 사례와 합성 대조 자료로 제품을 보완한다. 유지보수 구현·독립 검수 사용량은 연구 실측과 별개다.

## 목표와 판정

| 작업 | 확인할 동작 | 주장하지 않는 것 |
|---|---|---|
| 수정 중 조건 손실 | 실제 적용된 수정에서 제외·조건·부정 표지의 손실을 검토 신호로 표시 | 모든 의미 손실 탐지, 올바른 정정의 자동 오류 판정 |
| 근거 부족 수정 보류 | 발췌에 없다는 이유만으로 원문 내용을 지우지 않도록 제한적 보류 | 모델 비평의 사실성을 자동 확정 |
| 읽기 쉬운 검수 | 수정 전후와 finding 연결을 보여 사람의 확인 지원 | 자동 검사 통과가 전체 정확도를 보장 |
| 분석 동시 재사용 | 동일 조건·동일키의 선행 분석 완료 뒤 캐시를 재검사 | 캐시 적중을 실제 절감 토큰 수치로 기록 |
| 체험·제보 | 무호출 합성 미리보기와 제한된 메타데이터 수동 출력 | 실제 리서치 실행·외부 테스트 완료 |

## 적용 범위

제외·조건·부정 표지의 감소는 `patcher_numeric_audit.json` / `polish_numeric_audit.json`의 `qualifier_changes`에 수정 전후 전체 문장, 실제 적용 hunk 순서, finding ID와 함께 남긴다. `quality.json`과 `review.md`에는 검토 필요로 표시한다. 정상적인 정정·동의어 변경도 경고할 수 있으며 자동 거부하지 않는다.

비평 보류는 비평 응답의 명시적 근거 상태를 사용한다. 발췌가 불충분하다는 상태는 해당 수정 제안을 보류하고 사람이 확인할 대상으로 남긴다. 자유문장에 특정 단어가 있는지만으로 정상 정정을 보류하지 않는다. 이 상태는 모델의 자기보고이며 사실성 증명이 아니다. 과거 응답처럼 상태가 없으면 임의로 추론하지 않는다. 보류된 finding은 심각도가 낮더라도 삭제하거나 해결 완료로 처리하지 않고 최종 검토에 남긴다.

동시 분석 잠금은 `--reuse-analysis`를 켠 동일 작업 폴더·동일 분석 키에서만 적용한다. 대기 후 결과 구조와 입력 결속을 다시 확인한다. 생성 실패 후 잠금은 해제되고 다음 대기자는 정상 예산 검사 아래에서 생성할 수 있다. 대기 시간은 설정된 모델 timeout + 30초이며, 초과 시 중단해 무제한 대기하지 않는다. 캐시 저장 실패까지 단일 호출을 보장하지 않으며 실제 절감량을 추정해 원장에 넣지 않는다.

동시 실행 회귀에서 발견한 SQLite 색인 재생성 경쟁도 수정했다. DROP/CREATE/삽입을 하나의 쓰기 트랜잭션에 묶어 실패 시 되돌리고 연결을 닫는다. 분석 테스트에서도 실제 색인 동기화를 사용한다.

## 테스트 데이터의 경계

기존 실패 재생은 알려진 결함의 회귀검사다. 새로운 독립 평가가 아니다. 한국어·영어 합성 대조 자료에는 정상 정정과 조건이 유지된 문장도 포함한다. 규칙 밖 표현, 동의어, 인과관계는 여전히 사람이 확인해야 한다.

[앞선 측정](INLINE-MEASUREMENT-20260915.md)의 연구 토큰 16.0% 감소와 품질 5/6→4/6은 그대로다. 이 작업은 그 수치를 새 후보의 성과로 옮기지 않는다. 직접 입력 전달은 기본 OFF를 유지한다.

## 자발적 제보

`hpr demo`는 합성 형식 미리보기이며 Codex 로그인·네트워크·모델을 사용하지 않는다. `hpr feedback RUN_ID`는 기존 실행의 제한된 메타데이터를 stdout으로 출력하며 자동 전송하지 않는다. 원문·계정·경로를 포함한 전체 연구 폴더를 제출할 필요가 없다.

[제출 안내](FEEDBACK.md)와 [제보 분류·재현 기준](FEEDBACK-TRIAGE.md)을 따른다. 실제 외부 제보가 들어오기 전에는 사용자 성공률이나 일반 품질 향상을 계산하지 않는다. Windows 실제 모델·PyPI·새 릴리스·홍보 게시는 이 변경의 완료 조건과 분리한다.
