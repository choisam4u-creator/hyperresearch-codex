# 기존 데이터 기반 보완 — 2026-09-15

새 연구·평가 모델 호출 없이, [앞선 실측 자료](INLINE-MEASUREMENT-20260915.md)와 과거 20회 기록을 검토했다. 과거 판정·원문·사용량 및 공개 재현 패치는 수정하지 않았다. 아래 결과는 저장된 응답 재생과 mock 검증이며 새로운 실측 절감률이 아니다.

## 반영한 변경

| 기존 데이터에서 확인한 문제 | 수정 | 무호출 검증 |
|---|---|---|
| 산림 사례의 표현 수정이 분모 1,080 제외 조건까지 삭제했다. 프롬프트 보완만으로는 이후 삭제를 코드가 드러내지 못했다. | 실제 적용된 패치·다듬기에서 사라지거나 바뀐 숫자를 단계별 감사 파일에 남기고 최종 품질을 검토 필요로 표시한다. | 원래 실패 응답은 F2의 1,080 삭제를 검출하고, 앞서 통과한 수정 응답에서는 숫자 삭제 신호가 없다. |
| 비평가가 발췌에 없는 내용을 원문에도 없다고 단정해 올바른 초안에 수정 제안을 냈다. | 근거 비평에 발췌·요약의 범위를 명시하고, 확인 불가와 원문 모순을 구분하도록 안내한다. 한국어 비평의 파일 안내도 실제 발췌 파일명으로 맞춘다. | 실제 비평 호출 입력에 안내가 전달되는지 검사했다. 새 모델의 의미 판단 개선은 측정하지 않았다. |

## 숫자 수정 감사의 범위

`patcher_numeric_audit.json`과 `polish_numeric_audit.json`에는 실제 적용된 수정의 숫자 삭제·교체, finding ID, 입력/결과 해시를 기록한다. `[S1]` 같은 인용 ID와 `1,080.0`→`1080` 같은 표기 차이는 숫자 손실로 세지 않는다. 거부된 수정이나 전체 수정 게이트 실패도 적용된 손실로 세지 않는다. 동일한 수정 제안을 두 번 반환해 두 번째만 거부된 경우에도 첫 번째 실제 적용 기록을 보존한다.

숫자 정정도 검토 신호에 포함된다. 자동으로 틀렸다고 판정하거나 올바른 정정을 막는 기능은 아니다. 최종 `quality.json`에는 `numeric_removal_in_edit`와 감사 파일명이 표시되고 기존 규칙대로 CLI가 검토 필요 상태를 반환한다. 숫자가 없는 조건·단위·인과 관계의 손실까지 탐지하지는 못한다. 새로운 모델 호출은 추가하지 않는다.

## 분석 재사용의 범위

기존 `make_key`의 전체 값 결속은 유지하고, 분석 전용 키만 새 버전으로 분리했다. 질문·언어·기준일·모델·추론 강도·backend·프롬프트·스키마·코드·출처 해시·정확한 입력 파일 및 나머지 설정은 계속 비교한다. 후속 단계와 증분 분석의 전체 맥락 비교도 유지한다. 구형 키는 자동 변환하지 않는다.

과거 20회에서 분석 단계는 979,552토큰이었다. 동일 입력을 반복한 실험이 포함돼 있으므로 이 금액을 절약 가능한 실사용 비용으로 해석하지 않는다. 캐시 적중은 새 호출이나 가상의 절감 토큰으로 원장에 기록하지 않는다. 비교 실험은 독립적인 결과 생성이 필요하므로 계속 재사용을 꺼야 한다.

## 이번에 확장하지 않은 것

분석가·인용 검사까지 직접 전달을 넓히는 방안은 가설로 남긴다. 기존 writer/critic 전달의 관찰값을 다른 단계의 절감률로 옮길 수 없기 때문이다. 비평 안내에는 짧은 문구가 추가되므로 입력 자체가 줄었다고 주장하지 않는다. 이번 작업의 연구·평가 신규 호출은 0회이며 유지보수 대화 사용량과는 구분한다.
