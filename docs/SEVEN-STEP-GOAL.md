# 후속 1–7 작업과 검증 범위

2026-09-14. Windows 실제 모델 실행과 다른 사용자 테스트를 제외한 내부 개선이다. 구현 통과와 실제 정확도·토큰 절감 달성은 별도 판정한다.

| 번호 | 변경 | 확인 방법 |
|---|---|---|
| 1 | 질문 접두사만 제거하라는 알려진 형식 지적 억제, 동일 인용·문제 중복 통합, 결정적 형식 검사 | 실제 이전 pilot 지적 및 심각도 보존 회귀 |
| 2 | 지시 준수 비평에서 중복 출처 제외; Light 비평 2종 통합 선택 기능 | 전달 입력·호출 수·resume 검사. 출력 길이와 요구 사항 유지 |
| 3 | 문장 원자 주장에 조건·수치·비교 관계까지 포함하도록 범위 확인 | 생략·잘못된 출처·인용 누락 회귀. 문자 범위 충족만으로 의미적 진실을 보장하지 않음 |
| 4 | 보고서 해시에 묶인 전체 주장 후보·수동 판정 집계와 모델 정보 없는 검토 자료 | 추가 주장·잘못된 위치·미판정·이전 판정 누출 차단. 후보 목록 자체의 완전성은 사람이 확인 |

| 6 | 사전 지정한 비평/semantic 설정만 달라지는 실험 비교기 | 입력·모델·코드·프롬프트·출력·예산 통제. 실측은 별도 예산 확정 후 수행 |
| 7 | 단계별 사용량·실행별 잔여 기준·진행 중 예약·중단 이유 표시 | 미측정 호출과 병렬 중단 뒤 완료된 호출 회귀 |

`critic_policy.compact_inputs` 기본값은 true, `critic_policy.combine_light` 기본값은 false다. 통합은 Light의 dialectic/instruction 두 비평만 대상으로 하며 다른 비평을 버리지 않는다. `verification.semantic`은 기본 false다. 사용자 설정은 실행 디렉터리의 `research/config.json`에서 지정한다.

비평 통합은 모델 판단의 범위와 품질에 영향을 줄 수 있으므로 실제 비교 전 절감률을 홍보하지 않는다. 비용 안내는 계정 잔량이 아니라 해당 실행의 기록이며 예약값은 강제 과금 상한이 아니다.

## 후속 실측 계획 — 승인 후 6회 실행 완료

두 dev 질문을 각 세 가지 설정으로 실행한다. holdout은 이 설정 선택에 사용하지 않는다.

1. `real-ko-table`: 제시된 지역 냉방 시범사업의 성과를 수치·단위·조건과 함께 요약하라.
2. `real-en-boundary`: Compare the two archive routes while preserving their scope and boundary conditions.

| 설정 | compact_inputs | combine_light | semantic |
|---|---|---|---|
| 기준 | false | false | false |
| 절감 후보 | true | true | false |
| 세부 근거 검사 | true | true | true |

총 6회, 동일 Light lean·700단어 목표·고정 자료·기준일·코드·프롬프트·모델 배정. analyst/critic/patcher는 Terra, writer는 Sol, citecheck는 Astra로 고정하고 자동 모델 승격은 끈다. 공개 웹 검색·수집은 하지 않는다.

직전 pilot은 한 실행에 약 18만–24만 입력+출력 토큰이었다. 이번 자료가 더 길어 이 범위를 보장할 수 없다. 계획용 예상은 총 약 120만–180만 토큰이며, 중단 기준은 실행당 50만·합계 300만이다. 실행당 최대 8회 모델 호출, 전체 최대 48회, 재시도 0회. 사용량 미측정 또는 예산 중단이 발생하면 실험을 중단하고 자동 증액·재실행하지 않는다. 진행 중 호출이 끝나며 기준을 초과할 수 있다.

분석은 설정별 전체 입력+출력·실패·재시도·미측정·시간, 전체 주장 수동 검토 결과, 조건·인용 오류, 수정 횟수를 함께 보고한다. semantic ON/OFF의 샘플 오류 탐지 변화와 비용을 별도로 비교한다. 모델명을 숨긴 자료 생성 기능과 실제 독립 블라인드 판정 수행은 구분한다. 별도 유료 심판 호출은 이 계획에 포함하지 않는다.

구현 회귀가 통과해도 작은 dev 실험 6회로 전체 정확도나 원본 대비 우위를 확정하지 않는다. 결과가 나빠지면 선택 기능을 기본 활성화하지 않는다.

## 구현 검증 기록

전체 오프라인 회귀 299개 통과. 새 현실형 입력 6건 모두 mock 파이프라인에서 최종 보고서까지 생성했다. 별도 임시 venv에 wheel을 설치하여 저장소 밖 mock 완주와 추가 호출 없는 resume를 확인했다. 이는 모델 정확도 검사가 아니다.

Terra/Sol 구현 후 Astra가 요청 변경 범위를 검토하여 발견한 6건을 수정했고, 관련 61개 테스트와 실제 비평→최종 검사 연결을 재검수했다. 전체 저장소의 보안·의미 정확도 전수 감사는 아니다. 이후 사용자가 6회·합계 300만 토큰 중단 기준을 승인했다. 6회 실측을 완료했고 실제 1,426,492토큰을 사용했다. [결과와 한계](POLICY-MEASUREMENT-20260914.md)를 참조한다.
