# 토큰과 품질 실측 결과 — 2026-09-14

입력 패킷의 **일반적인 토큰 절감이나 품질 향상은 입증되지 않았다.** 개발 질문에서는 토큰이 늘었고, 보류 질문에서는 합계가 줄었지만 질문·반복별 방향이 달랐으며 품질 미확정과 오류가 남았다. `packet_inputs` 기본값은 OFF로 유지한다.

| 분리된 실험 | 실제 실행 | baseline 입력+출력 | packet 입력+출력 | packet 변화 |
|---|---:|---:|---:|---:|
| [개발 질문2개 × 각2회](results/packet-inputs-20260914/README.md) | 8 | 932,805 | 1,001,465 | **+7.36%** |

두 실험을 합쳐 일반 절감률을 만들지 않는다. 보류 실험6쌍 중4쌍은 토큰이 늘고2쌍은 줄었다. −3.18%는 이 표본의 합계 변화이며 ‘같은 품질에서 절약’이라는 뜻이 아니다.

총 연구 실행20회·모델 호출118회에 **4,840,608 입력+출력 토큰**을 기록했다. 실제 원장에 사용량 누락·재시도·실패한 모델 호출·실행 조건 불일치는 없었다. 보고서 생성은 품질 통과와 다르다. 자동 품질 경고와 전체 본문 블라인드 판정은 개별 결과에 분리해 공개한다. 캐시 입력은 이미 입력에 포함되며 다시 더하지 않았다. 유지보수·독립 검토 대화의 사용량은 위 연구 원장과 별개다.

## 무엇을 측정했나

동일 연구 코드 `53e6b790c79048edd782240e20374fc27cb6fec2`에서 Light lean, economy 역할 배정 고정, routing OFF, 같은 원문·질문·700단어 목표로 packet 설정만 바꿨다. Codex CLI `0.154.0-alpha.6.2`, macOS에서 순차 실행했다. 원문은 고정 합성 자료이고 외부 검색·다운로드 없는 replay다. 실재 제품·기관의 성능, 실제 웹 조사, 원본 Hyperresearch와의 품질 비교를 수행한 결과가 아니다.

조건 이름을 숨긴 보고서와 출처를 단일 Astra가 전체 본문 기준으로 판정했다. 같은 사실의 반복 등장도 원자 항목에 각각 포함하므로 이를 독립 사실 수나 일반 정확도로 환산하지 않는다. 판정별 근거 인용·원문 위치·해시를 검증했지만 그 검사가 판단자의 정확성이나 의미적 완전성을 자동 증명하지는 않는다. 사람의 외부 검증은 아직 없다.

각 결과 폴더에는 계획 공개 사본, 실패를 제외하지 않는 전수 사용량, 모델/역할/추론 강도, 실제 출력 분량, 원본 보고서, 블라인드 입력·판정·근거 위치를 포함했다. 개인 경로가 있는 원시 실행 로그와 블로그 자료는 비공개로 보존한다.

## 개별 기능과 두 프로젝트 적용

[관찰 자료와 재현 방법](results/feature-observations-20260914/README.md)에 분석 재사용·변경분 갱신·Full 경로의 mock 기록과 두 블로그의 근거 메모·계산 검증 범위를 정리했다.

- 재사용은 최초7호출, 동일 입력 재사용6호출이었다. 갱신은 무변경 분석0회, 변경·삭제 증분 분석 각1회였다.
- Full facts 경로는 mock에서12→9호출이며 조사·비평·인용검사를 유지했다. 이 호출 수를 실제 토큰 절감률로 바꾸지 않는다.
- 근거 선택은 두 개발 질문의 mock 비교에서 실제 전달 입력 해시가 같아 승인된 실제4회 실행을 생략했다. 해당200만 토큰 중단 기준 예산은 사용하거나 재배정하지 않았다.
- 두 블로그에서는 원문 수치·SHA·구간에 연결한 계산과 근거 메모를 만들었다. CMS·게시·자동화는 바꾸지 않았고 제작비·시간·품질 개선률을 측정하지 않았다.
