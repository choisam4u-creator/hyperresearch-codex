# 품질 비교 준비: 평가자 보정 중단 결과

**품질 향상은 아직 입증하지 못했다.** 수정 전후 연구를 시작하기 전에 평가자부터 시험했으나, 첫 호출이 호출당 중단 기준을 넘고 전체 검토도 확정하지 못해 중단했다. 연구를 반복해도 신뢰할 평가가 없는 상태에서 비용만 늘어날 수 있어 후속 호출은 하지 않았다.

## 확보한 데이터

[공개 데이터 묶음](results/quality-calibration-20260915/)에는 합성 원문과 질문, 사례별 필수 항목8개, 원문에 결속한 정답표, 익명 보정 예제6개, 숨겨 둔 정답 매핑, 실제 평가 응답, 사용량, 평가 프롬프트·스키마와 SHA256 목록을 담았다. 개인 경로가 포함된 CLI 원시 로그는 공개하지 않는다. 이전20회 실측과 별도이며 이전 결과를 덮어쓰지 않았다.

| 항목 | 관측값 |
|---|---:|
| 실제 평가 호출 | Terra low 1회 |
| 수정 전후 연구 실행 | 0회 |
| 평가 입력 토큰 | 80,016 |
| 위 입력에 포함된 캐시 토큰 | 45,568 |
| 평가 출력 토큰 | 6,017 |
| 입력+출력 합계 | **86,033** |
| 호출당 중단 기준 / 초과분 | 60,000 / 26,033 |
| 올바른 예제 중 통과 | 0/2 |
| 의도한 오류를 찾은 오류 예제 | 4/4 |
| 전체 검토 완료 응답 | 0/6 |

캐시 토큰을 합계에 다시 더하지 않는다. 총 승인 중단 기준150만의 약5.74%를 사용했다. 연구120만·평가30만은 별도 pool이며, 미사용분은 자동 재시도나 추가 실행에 쓰지 않았다. 호출 종료 후 실제 사용량을 받으므로60,000은 강제 청구 상한이 아니다. 유지보수 대화와 검수의 일반 사용량은 이 수치에 포함되지 않았고 미계측이다.

다음 명령으로 데이터 해시·인용구·예제 매핑·사용량·집계를 모델 호출 없이 다시 검사할 수 있다. 무결성 통과는 의미 판정의 정확성이나 품질 향상 통과가 아니다.

```sh
python3 docs/results/quality-calibration-20260915/verify.py
```

## 무엇이 확인됐나

평가자는 네 오류 예제의 의도한 오류를 지적했지만, 여섯 응답 모두 입력 잘림을 이유로 전체 검토를 확정하지 않았다. 따라서4/4를 신뢰할 수 있는 일반 오류 탐지율이나 평가자 보정 통과로 해석하지 않는다. 올바른 두 예제는 `eval_unavailable`이었다. 이 예제별 대조는 중단 후 저장된 응답을 오프라인에서 집계한 것이며, 연구 시작 게이트를 사후 통과시키지 않았다.

CLI 기록에는 파일을 읽는 명령2개가 있다. 첫 명령의 저장된 출력에는 전체 compact 입력이 정확히 포함돼 있고, 두 번째 명령은 기준표·보고서를 다시 읽었다. **평가자가 실제로 본 도구 출력의 잘림 여부와 경계는 이 기록만으로 확정하지 못했다.** 중복 읽기는 관찰했지만 이것이 추가로 몇 토큰을 썼는지는 분리 측정하지 못했다. 단순히 원문 파일이 누락됐다고 진단하지 않는다.

두 버전의 연구 결과가 없으므로 정확도 상승, 토큰 절감률, 품질을 충족한 보고서당 비용은 계산하지 않는다. 정답 예제6개는 평가 장치 진단용이며 새 질문6개나 독립 표본6건이 아니다. 외부 사용자 검증도 아니다.

## 다음 작업

1. 추가 모델 호출 없이, 평가 입력을 파일 읽기 도구의 출력으로 전달하는 구조를 개선할 후보를 준비한다. 원문·평가기준·예제를 직접 입력에 넣고 중복을 제거하되 필수 근거를 삭제하지 않는 방향이다.
2. 입력의 모든 원문·예제·필수 항목이 보존됐는지 오프라인 검증하고, 기존 실패 응답을 이용해 집계와 중단 검사가 올바르게 작동하는지 재현한다. 이 검사는 모델이 실제로 읽었다는 증거는 아니다.
3. 전달 방식 변경은 기존 실험과 구분한 새 계약으로 검수한다. 새 실제 호출은 별도 범위·예산 확인 후에만 한다. 보정이 통과하기 전 수정 전후 연구4회와 후속12회는 실행하지 않는다.

이 결과는 평가 장치의 비용과 미확정 원인을 좁히는 자료다. 제품 품질이 좋아졌다는 성과로 제시하지 않는다.
