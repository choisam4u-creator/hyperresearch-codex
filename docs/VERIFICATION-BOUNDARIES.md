# 날짜·부호·수량 검증의 범위

`quality.json`의 검토 신호는 모델 호출 없이 만든다. `passed`는 전체 사실성이 보장된다는 뜻이 아니다.

| 표현 | 처리 |
| --- | --- |
| 같은 줄의 `2026년 7월 22일과 8월 6일` | 명시 날짜에 바로 병렬 연결된 단일 월·일에만 연도를 보충한다. 보고서와 원문 각각에서 독립적으로 해석한다. |
| 원문에 연도가 없거나 다른 문장·줄·출처에만 있음 | 보고서의 연도로 원문을 보충하지 않고 날짜 검토를 유지한다. 현재 연도나 게시일도 사용하지 않는다. |
| 같은 크기의 양수와 음수 | 자동으로 같은 값으로 처리하지 않는다. `numeric_sign_context_unclear`로 부호와 감소량 표현의 의미 검토가 필요함을 알린다. |
| `곳`과 `개소` | 같은 장소 수량 단위로 비교하되 기존 문맥 검사도 유지한다. |
| `개`, `곳`, `대`, `회`, `종` | 서로 다른 수량 단위로 구분한다. 숫자가 같거나 문맥 낱말이 겹쳐도 단위를 합치지 않는다. |

이 규칙은 한국어 전체 문법이나 모든 단위를 지원하는 분석기가 아니다. 복잡한 날짜 나열·생략과 부호의 의미 해석은 검토 대상으로 남을 수 있다. 정상/오류 회귀 사례의 통과와 실제 보고서의 정확도·토큰 절감률 실측을 구분한다.
