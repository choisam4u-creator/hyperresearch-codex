# 페이즈별 개발 계획

2026-09-14 기준. 원본의 기능을 그대로 늘리기보다 짧고 검증 가능한 Codex 브리핑이라는 목적을 유지한다. Phase 1은 현재 구현 범위이며, 다음 단계는 계획이다. 실제 리서치 호출·배포는 구현 승인과 구분한다.

Phase 1 로컬 구현·Astra 검수 완료: 회귀 테스트 112개 통과, 임시 환경 wheel 설치 후 mock Light 완주·추가 호출 없는 재개 확인. 실제 리서치 모델 호출은 하지 않았다. 이번 변경의 원격 CI·Windows 검증과 구분한다.

| 페이즈 | 목표·작업 | 완료 조건 | 실행 비용·의존성 |
|---|---|---|---|
| **1. 근거 보존과 경로 정정** | 불변 출처 스냅샷·실행별 S번호 매핑, run/resume/status/MCP 실행 ID 경계, 날짜 전달, 원본 비교표 정정 | 두 실행의 같은 S1/제목도 이전 본문 보존. 날짜가 모델 입력에 전달. 상위경로·절대경로·외부 symlink 거부. 기존 정상 실행·구형 노트 호환 | mock/임시 파일 검증. 실제 리서치 호출 없음 |
| **2. 외부 자료 처리** | 웹 본문을 데이터로 구분, 위조 경계문자 무력화, URL·redirect·사설주소 정책 | 본문 안 명령은 지침과 구분. 가짜 주입·redirect 회귀. 명시적 로컬 자료와 자동 검색 URL 정책 구분 | 기본은 오프라인 fixture. 실제 모델에 대한 효과는 별도 확인 |
| **3. 최종 보고서 검증** | 생성 완료/검증 통과 상태 분리, 직접 인용 원문 확인, 숫자·단위·날짜 대조, 다듬기로 바뀐 주장 검사 | 심각한 미해결 항목은 통과로 표시하지 않음. 반올림·환산 오탐 fixture. 변경 없는 문장은 불필요하게 재호출하지 않음 | 정적 검사 먼저. 추가 모델 검사는 범위·예산 명시 |
| **4. 누락 근거 보충** | Full에서 중요 gap에 대한 검색·수집 한 번 추가, 근거 요약 갱신 | 중요 gap 1~2개·출처 2~3개 등 작은 상한. no-search·HardStop·예산 유지. 실패하면 한계로 남김. 중단 후 중복 호출 없이 재개 | Phase 2·3 선행. 실제 검증은 고정 질문·예산 승인 후 |
| **5. 기존 자료 재사용** | 새 조사 전 FTS 검색, 출처·내용·최신성 확인, 필요한 자료만 갱신 | 영구 note ID와 실행별 별칭 연결. 만료/수정 자료 갱신. 현재 run이 과거 run의 원본을 바꾸지 않음 | Phase 1 선행. 캐시 적중률·절감량은 실측 전 보장하지 않음 |
| **6. 품질·비용 평가** | 한영 사실형·비교형·논쟁형 고정 질문, 필수 주장과 출처 정답, 토큰·시간·근거 누락·인용 지지율 기록 | 같은 자료/설정에서 개선 전후 비교. 원본 공개 보고서는 입력 차이를 밝힌 참고 평가. 분량 감소만으로 성공 판정 금지 | 평가 자료 설계는 Phase 3부터. 실제 실행은 별도 예산 확정 |
| **7. 설치·공개 운영** | 다른 컴퓨터·Windows, 스킬 배포 경로, 의존성 업데이트, 소규모 설치 피드백 | 환경별 install/help/mock 증거. 지원 범위 문서 일치. 자발적 피드백 반영. 변경 로그·버전·릴리스 범위 정리 | Windows 환경 필요. 외부 연락·PR 병합·릴리스는 사용자 확인 |

각 페이즈는 관련 회귀 테스트와 Astra 최종 검수를 거쳐 로컬 커밋으로 묶는다. GitHub 푸시는 사용자 요청 범위에서 수행한다. 모델 배정은 실행·무결성 수정에 Sol, 자료 처리·파이프라인에 Terra, 문서·설치 보조에 Luna를 기본으로 삼되 실제 난도에 따라 조정한다.

나중에 검토할 확장은 목적별 설명/비교/분석 모드와 DOI·철회 여부·출처 종류의 품질 메타다. 대형 대시보드·수백 출처·장문 전용 모드는 위 검증보다 우선하지 않는다.

기존 노트는 이동하거나 다시 쓰지 않는다. 과거에 이미 덮어쓴 내용은 이 변경만으로 복구되지 않는다. 기존 자료의 자동 재사용은 Phase 5까지 구현된 것으로 설명하지 않는다.
