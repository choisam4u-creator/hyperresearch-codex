# 입력 효율과 조사 갱신

이 기능들은 실제 토큰 절감률이 입증된 기본값이 아니라 선택 실험이다. 준비 입력의 바이트 감소·mock 호출 감소와 실제 Codex 토큰·품질 실측을 구분한다. 실행 경로·분석 재사용·입력 선택은 기본 OFF이며 기존 인용 검증을 유지한다.

## 구현 순서와 범위

| 단계 | 기능 | 현재 범위 |
| --- | --- | --- |
| 1 | 반복 입력 진단 | `input_profiles.json`에 파일별 준비 바이트·해시·동일 입력 반복을 기록한다. `hpr profile RUN_ID`는 실제 단계별 사용량과 구분해 출력한다. 부분적으로 겹치는 문장 전체를 탐지하는 기능은 아니다. |
| 2 | 작성·비평 입력 묶음 | `--packet-inputs`는 writer의 중복 digest를 구조·출처 메타 확인 후 제거하고, 작성·비평 입력을 한 파일의 가상 파일 섹션으로 전달한다. 원문 wrapper를 보존한다. 패킷 자체의 표식도 입력에 포함되므로 절감은 미측정이다. |
| 3 | 주장별 근거 범위 확인 | `--evidence-selection`은 질문/보고서 문장들의 공유 발췌 상한 안에서 조건·반대 근거 후보를 선택하고, 원문 위치·누락·문장별 단어 coverage를 기록한다. coverage는 의미 지지·완전성 판정이 아니다. |
| 4 | 같은 조건의 분석 재사용 | `--reuse-analysis`는 질문·언어·기준일·전체 설정·코드·프롬프트·스키마·모델·backend·원문 해시·실제 분석 입력이 일치하고 캐시 무결성이 확인될 때 분석 산출물만 재사용한다. 재사용은 새 모델 호출/가상의 절감 토큰으로 장부에 넣지 않는다. |
| 5 | 형식별 실행 경로 | `--strategy adaptive --tier full --format facts`는 단일 초안으로 작성하고 별도 종합·다듬기를 생략한다. 조사·비평·인용 검사는 유지한다. 다른 형식과 standard 경로는 유지한다. |
| 6 | 변경분 분석과 비교 | `--update-from BEFORE`는 동일 분석 맥락에서 불변 출처의 주장만 재사용하고, 변경된 출처 및 영향을 받는 주장의 함께 인용된 원문만 분석한다. 모순·빈틈은 재평가하며 작성·검증은 다시 수행한다. 분석 맥락이나 출처 무결성이 불명확하면 전체 분석으로 돌아간다. |
| 7 | 사용자 검토 도구 | `hpr evidence RUN_ID`의 근거 비교표, `hpr changes BEFORE AFTER`의 출처/주장 변경표, 원문 위치에 묶인 계산 검산을 제공한다. 예산 안내는 실행 계획과 기존 cost guidance에 연결된다. |

## 먼저 호출 없는 계획 확인

```bash
hpr run "검토할 질문" --tier full --format facts --strategy adaptive --packet-inputs --evidence-selection --reuse-analysis --plan-json
```

`--plan-json` 없이 실행하면 실제 리서치 호출을 한다. 결과 품질과 토큰 비용을 같은 입력·출력 조건으로 실측한 뒤 선택 기능 채택 여부를 판단해야 한다. 동시에 여러 설정을 바꿔 절감의 원인을 주장하지 않는다.

## 작성·비평 입력 직접 전달

`--inline-inputs`는 writer와 비평 단계가 준비한 입력 파일명·본문을 프롬프트에 직접 포함하고 stdin으로 전달하는 선택 기능이다. 기본값은 OFF다. source wrapper와 준비된 원문을 보존하며, 기존의 검색·분석·수정·인용 검사와 예산·사용량 기록은 유지한다. 전체 원문을 새로 수집하거나 발췌 상한을 없애는 기능은 아니다.

```bash
hpr run "검토할 질문" --tier light --inline-inputs --plan-json
```

`--plan-json`을 빼면 실제 모델을 호출한다. `--packet-inputs`와는 함께 사용하지 않는다. 직접 전달은 packet 방식의 writer digest 제거를 적용하지 않으므로, 전달 방식만 비교할 때는 기존 파일 전달(`packet_inputs=false`, `inline_inputs=false`)과 비교한다. 두 옵션을 섞어 입력 축약 효과로 해석하지 않는다.

`input_profiles.json`은 원래 준비 입력과 `delivery: inline_prompt_stdin`을 남긴다. 준비 바이트는 실제 토큰이 아니며, 모델이 도구 읽기를 생략하는지와 전체 보고서 품질은 실측으로 별도 확인해야 한다. 큰 입력도 운영체제 명령줄 인자에 넣지 않는다.

## 반복 실행과 갱신

```bash
hpr run "기존과 같은 질문" --run-id new-run --update-from old-run --total-budget 500000
hpr changes old-run new-run
hpr profile new-run
hpr evidence new-run
```

새 실행에는 새 ID를 쓴다. 위 실행도 실제 모델을 호출할 수 있다. 출처 검색·수집은 기존 절차를 따르며 변경분만 네트워크에서 내려받는 기능은 아니다. 재사용하는 것은 분석의 일부이고, 최종 보고서 전체 문단의 무조건 재사용은 아니다. 같은 출처라도 기준일·설정·코드·프롬프트가 달라지면 전체 분석이 필요하다. 삭제된 출처의 주장, 다른 출처의 연도, 손상된 노트를 현재 근거로 채택하지 않는다. 과거 주장은 모델의 주장이지 진실 인증이 아니다.

`update_plan.json`에는 재사용/무효화된 주장과 재분석 출처를, `changes.json`에는 완료된 두 실행의 차이를 남긴다. 변경 없음은 최신성 인증이 아니다. 원본 실행은 수정하지 않는다.

## 원문에 묶인 계산 검산

`hpr calculate RUN_ID calculation.json`은 모델 호출 없이 계산 JSON을 확인한다. 자동으로 보고서 전체의 모든 산술 문장을 이해하는 기능은 아니다. 계산값의 의미·분모 선택·표본 적절성은 별도 검토한다.

```json
{
  "operation": "percent_change",
  "operands": [
    {"source_id": "S1", "start": 0, "end": 5, "quote": "10 kW", "unit": "kW"},
    {"source_id": "S2", "start": 0, "end": 5, "quote": "15 kW", "unit": "kW"}
  ],
  "expected": "50"
}
```

위 위치는 예시다. 실제 `sources.json`의 note에 대한 `vault.note_body()` 원문 문자 위치와 일치해야 한다. 결과에는 원문 해시·인용 구절·위치를 남긴다. `sum`, `mean`, `difference`(두 번째−첫 번째), `percent_change`((두 번째−첫 번째)/첫 번째×100)를 지원한다. 단위는 정확히 같아야 하며 단위 변환을 추정하지 않는다. 분모 0·인용 불일치·잘린 숫자를 거부하고 예상값은 정확 비교한다.

## 검증 경계

직접 입력 전달은 [6쌍 실측](INLINE-MEASUREMENT-20260915.md)에서 연구 토큰이 16.0% 줄었지만 전체 본문 통과도 5/6→4/6으로 줄었다. 옵션은 기본 OFF이며 일반적인 품질 유지·절감은 입증하지 않았다. 알려진 출처 메타 오류와 패치 조건 누락의 수정 검증은 별도 결과다. 나머지 선택 기능의 실제 절감률은 이 결과로 추정하지 않는다.

외부 사용자·실제 Windows 모델 실행은 검증 범위 밖이다. 회귀와 CI의 mock·설치 검사는 실제 정확도·절감률을 대신하지 않는다. 공개 비교에는 실패·재시도 비용, 필수 내용 누락, 치명 오류, 품질 충족 보고서당 전체 토큰을 함께 기록한다.
