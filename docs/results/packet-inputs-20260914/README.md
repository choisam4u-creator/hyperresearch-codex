# 입력 패킷 개발 질문 파일럿 — 2026-09-14

실제 Codex 연구 실행 8회. 고정 합성 질문 2개를 두 조건으로 각각 2회 반복했다. 이 표본에서 packet 입력은 기본 입력보다 총 입력+출력 토큰을 **7.36% 더 사용**했다. 절감은 입증되지 않았으며 기본값을 바꾸지 않는다.

| 조건 | 입력+출력 토큰 | 순차 실행 시간 합 | Astra 통과/미확정/실패 |
|---|---:|---:|---|
| baseline | 932,805 | 550.3초 | 2/0/2 |
| packet | 1,001,465 | 649.6초 | 1/3/0 |

캐시 입력은 입력에 포함되므로 다시 더하지 않았다. 실행 시간은 각 subprocess의 벽시계 시간이며 심판·유지보수 대화 시간과 사용량은 포함하지 않는다. 구독 잔량 또는 청구 비용을 측정한 결과가 아니다.

## 조건과 재현

- 연구 코드: `53e6b790c79048edd782240e20374fc27cb6fec2`, Codex CLI `0.154.0-alpha.6.2`, macOS.
- `realistic-synthetic-v1`의 dev `real-ko-table`, `real-en-boundary`; 고정 replay라 외부 검색·다운로드 없음.
- Light lean, economy 역할 배정 고정, routing OFF. 두 조건 사이에는 `efficiency.packet_inputs`만 변경.
- 질문별 첫 반복 baseline→packet, 두 번째 packet→baseline. 완전 무작위 순서는 아니다.
- 실행당 50만·총400만 토큰 중단 기준, 최대8호출, 재시도0. 실제 합계는 1,934,270이다. 진행 중 초과를 막는 강제 청구 상한은 아니다.
- `status=ok`는 연구 실행이 보고서를 만들었다는 뜻이다. 본문 정확성 통과가 아니다. `pipeline_quality_status`, `blind_quality`를 별도로 기록했다.
- 조건 차이·실제 입력·모델/역할·사용량 필드와 해시를 검증했고, 8개 실행 모두 비교 조건 오류나 사용량 누락이 없었다. 토큰에는 적용되지 않은 수정 제안 등 모든 기록된 호출도 포함된다.
- 사전에 공개한 [계획](../../EFFICIENCY-STUDY-PROTOCOL.md)을 따라 로컬 실행 계획을 고정했다. 외부 사전등록 서비스나 독립 인적 검증을 거친 실험은 아니다.

이 코드로 체크아웃 후 `python3 -m hprc.study_runner`가 계획을 출력한다. 실제 재현에는 별도 사용자 예산 승인과 새 출력 폴더가 필요하다. 모델의 확률적 출력과 서비스 변화 때문에 토큰·본문의 완전 일치를 보장하지 않는다. 이 데이터의 설정·원문 버전·코드 해시를 먼저 비교한다.

## 품질 검토와 해석 한계

조건 이름을 숨긴 질문·원문·보고서 패킷을 단일 Astra가 전체 본문 기준으로 검토했다. 원자 항목에는 같은 사실의 반복 등장도 각각 포함된다. 이 분모를 독립 사실 수나 일반 정확도로 해석하지 않는다. 모든 판정의 원문 인용·위치·보고서/출처 SHA 결속은 프로그램으로 확인했지만, 의미적 완전성이나 판정자의 정확성을 자동 증명한 것은 아니다.

baseline 보고서 1개는 원문 부록에 있는 절차를 없다고 썼고, 다른 1개는 측정 조건을 일반 실행 전제조건으로 확대했다. packet 조건에도 근거 부족 및 검증 불가능한 메타 진술이 남았다. 따라서 같은 품질의 결과를 더 싸게 얻었다거나 정확도가 개선됐다고 주장할 수 없다. 출처별 인용 세부 불일치와 process 진술은 개별 판정에서 사실 모순과 구분했다.

보류 질문 결과와 이 개발 결과를 합쳐 일반 성능을 주장하지 않는다. 원본 Hyperresearch나 다른 모델·검색 서비스와의 대조 실험도 아니다.
