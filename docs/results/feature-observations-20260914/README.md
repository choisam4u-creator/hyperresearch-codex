# 개별 기능과 블로그 자료 적용 — 2026-09-14

이 자료는 실제 토큰 절감 실험과 구분한 **오프라인 동작 관찰 및 비공개 원문 계산 검증**이다. 모델 품질 향상·실제 토큰 절감률은 측정하지 않았다.

## 개별 기능 관찰

| 기능 | 고정 mock 관찰 | 해석 범위 |
|---|---|---|
| 분석 재사용 | 최초 생성 7호출, 동일 입력 재사용 6호출; 분석가 1→0 | 캐시 최초 생성 비용 포함. 실제 모델의 토큰·품질 효과는 미측정 |
| 원문 갱신 | 무변경은 분석가 호출0, 변경·삭제는 증분 분석가 각1호출 | 변경 범위에 따른 분기 확인; 정확도 개선 증거가 아님 |
| Full facts 경로 | standard 12호출, adaptive 9호출 | 동일 사실형 요구. loci·조사·비평3개·인용검사 유지; 실제 품질 동등성 미확인 |
| 근거 선택 | 두 개발 질문에서 OFF/ON의 단계별 전달 입력 해시가 모두 같음 | mock 생성 내용에 대한 관찰. 실제 모델에서도 항상 같다는 뜻이 아님 |

근거 선택은 기본 설정 및 공통 축소 상한에서 비교를 사전 점검했다. 최종 점검의 공통 상한은 note 400자 / excerpt 200자다. selection artifact와 생략 구간은 생겼으나 전달 입력이 같은 비교로 선택 효과를 측정할 근거가 없어, 승인된 실제4회·200만 토큰 중단 기준 실험을 실행하지 않았다. 이 예산을 다른 실험에 재배정하지 않았다.

근거 선택의 다음 실측에는 실제 전달 입력이 달라지는 대표 자료와 평가 기준을 결과 확인 전에 새로 고정해야 한다. 같은 보류 질문을 반복 튜닝하면서 새 독립 평가라고 부르지 않는다.

## 두 블로그 프로젝트에서 확인한 사용 방식

비공개 프로젝트 자료로 원문 근거 메모와 계산 검증 입력을 만들었다. 개인 자료·원문·경로는 공개하지 않는다. CMS 변경·게시·자동화 연결·외부 화면 확인은 수행하지 않았다.

- 연구 도구 소개 글: 과거 실행 manifest의 단계별 입력 토큰 각각18개를 원문 위치와 SHA에 연결하고 합계를 검증했다. 서로 다른 버전의 과거2회이므로 같은 품질의 절감률이나 현행 기능의 인과 효과로 해석하지 않는다. 합계가 원문에 단일 값으로 없으므로 합계 간 변화율을 원문 직접 결속 계산으로 위장하지 않았다.
- 기기 문제 해결 글: 비식별 화면 정보의 두 주사율을 원문 위치에 연결해 차이0 Hz를 확인했다. 실제 고장 재현·복구 성공·모든 안내 절차의 공식 근거가 확보된 것은 아니다. 파생 스냅샷의 원본 변환 과정도 독립 검증할 수 없었다.

이 방식은 숫자 계산 오류와 근거 누락을 검토할 자료를 남기는 데 사용할 수 있다. 현재 계산기는 합계·평균·차이·변화율을 지원하며 픽셀 수 같은 곱셈 계산은 지원하지 않는다. 이번 적용에서 절약된 제작 시간·사용 토큰·발행 품질 개선률은 측정하지 않았다.
