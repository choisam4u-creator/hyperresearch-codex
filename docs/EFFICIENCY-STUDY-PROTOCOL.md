# 효율 데이터 확보 계획

상태: 개발8회와 보류12회 실제 실행 및 결과 공개 작업 완료. [실측 결과와 한계](EFFICIENCY-RESULTS-20260914.md)를 함께 읽는다. 이 문서의 새 실행에는 별도 예산 승인이 필요하다.

후속 품질 비교의 [평가자 보정 중단 결과](QUALITY-CALIBRATION-20260915.md): 평가1회86,033토큰, 연구0회. 제품 품질 향상은 미입증이다.

## 공개할 데이터

사용자는 같은 요구를 만족하는 결과를 더 적은 토큰으로 얻는지 확인할 수 있어야 한다. 공개 자료는 코드·프롬프트·모델·입력 해시, 정책 차이, 실행 순서, 실패/중단 포함 원시 사용량, 출력 보고서, 검토 기준과 판정 한계를 함께 제공한다. 캐시 토큰은 입력 합계에 이미 포함되므로 다시 더하지 않는다. 합성 고정 원문 replay와 실제 웹 검색 성능을 구분한다.

## 1차 실측의 고정 조건

- 입력: `tests/fixtures/realistic_inputs.json`의 dev `real-ko-table`, `real-en-boundary`. 정답은 실행 입력에서 분리한다. 보류 입력은 지금 튜닝하지 않는다.
- 정책: 같은 현재 코드에서 `efficiency.packet_inputs`만 false/true. evidence_selection/reuse_analysis OFF, strategy standard, 기존 비평 정책·semantic 고정.
- Light lean, 같은 질문·언어·기준일·출처·700단어 목표·형식·모델·추론 강도·예산.
- 모델은 기존 economy 역할 배정으로 고정하되 routing 자동 승격 OFF. 모델 배정의 우위 실험이 아니다.
- 질문마다 첫 반복 baseline→packet, 두 번째 반복 packet→baseline. 병렬 실행하지 않는다. 이 고정 교차 순서는 순서 영향을 줄이려는 장치이며 완전한 무작위 실험이 아니다.
- 실행당 최대 호출 8회, 재시도 0회. 실패·중단·미측정은 기록하고 해당 실험을 중단한다. 품질 검토 필요(exit 3)는 숨기지 않고 결과로 보존한다.
- 실행 시작 전 다음 50만 기준을 확보할 합계 여유가 있는지 확인한다. 미측정 호출 뒤 추가 실행하지 않는다. 실행 중인 호출의 초과 가능성이 있으므로 400만은 강제 결제 상한이 아니다.
- 평가용 별도 `codex exec`/API 심판 호출은 자동 실행하지 않는다. 독립 검수 대화의 일반 사용량은 위 리서치 파이프라인 토큰과 별개이며 이를 합산 비용 0이라고 주장하지 않는다.

## 판정 규칙

토큰 지표는 실패와 재시도를 포함한 총 입력+출력, 입력, 캐시 입력, 출력, 시간, 호출 수를 모두 남긴다. 네 쌍의 차이와 질문/반복별 방향을 먼저 제시하고 합계 절감률은 보조 지표로 쓴다. 두 질문만으로 유의미한 일반화·모델 순위·원본 오픈소스 대비 우위를 주장하지 않는다.

품질은 자동 passed와 분리한다. 전체 본문 원자 사실의 근거, 필수 질문 항목 충족, 치명 오류, 조건/인용 누락을 명시 판정하고 보고서 해시·출처 구간에 연결한다. 판정 누락은 통과가 아니다. 단일 Astra 검토는 단일 모델 판정이며 사람의 독립 외부 검증과 다르다. 후보와 baseline의 품질이 모두 확인되기 전에는 '같은 품질에서 절약'이라고 표시하지 않는다.

자료 선택·최종 길이가 달라질 수 있으므로 요구한 분량과 실제 분량도 공개한다. 검사 경고를 줄인 결과를 사실 오류 탐지율 개선으로 바꾸지 않는다. 보류 실험 실패 시 개발 데이터로 돌아가 수정하되 같은 보류 데이터를 계속 새 평가처럼 사용하지 않는다.

## 공개와 비공개

공개: 재현 명령, 버전/해시, 합성 입력, 정책 설정, 성공·실패 전수 집계, 비식별 보고서 및 판정, 제한 사항. 비공개: 계정/인증 정보, 개인 경로가 든 CLI 원시 로그, 블로그 운영 자료. 비공개 원시 기록은 로컬에서 보존하고 공개 내보내기는 별도 검수한다.

## 실행 도구

저장소 루트에서 계획만 확인한다. 기본 명령은 모델을 호출하지 않는다.

```sh
python3 -m hprc.study_runner
```

실제 모델을 호출하지 않는 모의 점검은 새 비공개 출력 폴더를 지정한다.

```sh
python3 -m hprc.study_runner --mock --repetitions 1 --output research/experiments/packet-mock-001
```

실제 실행 전에 계획을 파일로 고정한다. 명시적인 사용자 예산 승인 후에만 그 계획을 `--plan`으로 전달한다.

```sh
python3 -m hprc.study_runner > research/packet-plan.json
python3 -m hprc.study_runner --execute --plan research/packet-plan.json --approved-total-tokens 4000000 --output research/experiments/packet-new
```

실제 실행은 새 출력 폴더를 사용한다. 4회 탐색 승인을 받았다면 `--repetitions 1 --approved-total-tokens 2000000`을 사용한다. 이 숫자는 다음 실행을 중단하는 기준이며 구독 사용량이나 청구액의 강제 상한이 아니다. 실행 전 `python3 hpr.py doctor`로 환경을 확인한다. 실제 실행은 커밋된 깨끗한 checkout에서만 진행하며, 각 호출 전후 코드·프롬프트·설정·입력 변화가 있으면 기록된 비용을 보존하고 중단한다. 사용량 필드 일부가 누락되면 알려진 값은 남기되 미측정 호출로 분류한다.

`plan.json`은 사전 계획, `experiment.json`은 실패까지 포함한 실행 장부, `summary.json`은 비교 가능 여부다. `blind/`는 조건 이름을 제거한 검토 자료이며 각 실행 폴더의 identity 자료와 분리해 검토자에게 제공한다. 자동 집계는 품질 판정을 만들지 않는다. 전체 본문 검토의 판정과 근거, 보고서 해시를 별도로 남긴 뒤 공개 보고서에서 토큰 결과와 함께 해석해야 한다. 모의 실행 결과로 절감률이나 품질 개선을 주장할 수 없다.

같은 출력 폴더는 재사용할 수 없다. 중단되거나 사용량을 알 수 없는 호출은 원본 로그를 확인하기 전 재실행하지 않는다. 출력 폴더와 원시 로그는 기본 비공개이며, 공개 시에는 개인정보·로컬 경로를 제거한 결과만 별도 검수한다.
