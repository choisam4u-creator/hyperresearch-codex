# 비평 통합과 세부 근거 검사: 6회 실측

2026-09-14. **이번 실험에서는 비평 통합의 토큰 절감을 입증하지 못했다.** 호출은 줄었지만 두 질문 합계 토큰은 약 1.0% 증가했다. 세부 근거 검사도 비용·탐지 성능의 일반적 우위를 확정할 수 없어 선택 기능을 기본 활성화하지 않는다.

## 조건과 실제 사용량

실측 코드는 `94ba328e746d623f20b99f1c096698e58922f4be`다. 공개된 `tests/fixtures/realistic_inputs.json`의 dev 질문 `real-ko-table`과 `real-en-boundary`를 각각 세 설정으로 한 번씩 실행했다. 합성 자료이며 holdout 두 건은 실행하지 않았다. 외부 검색·다운로드 없이 고정 원문을 replay했다.

세 설정은 기준(compact_inputs=false, combine_light=false, semantic=false), 비평 통합(true,true,false), 통합+세부 근거(true,true,true)다. Light lean, 700단어 목표, 입력·기준일·모델·출력 형식·예산·코드·프롬프트 모음 버전은 각 질문 내 동일하게 고정했다. 각 설정이 선택하는 비평·인용 검사 프롬프트의 차이는 실험 처치에 포함된다. analyst/critic/patcher는 Terra, writer는 Sol, citecheck는 Astra이고 자동 승격은 껐다. 설정 비교기는 허용된 정책 값 외 변경이 없고 호출별 실행 메타데이터가 일치함을 네 비교 쌍에서 확인했다.

사용자는 6회, 실행당 50만·합계 300만 입력+출력 토큰 중단 기준을 승인했다. 실행당 최대 8회 호출, 재시도 0회, 미측정 시 중단 조건을 적용했다. 실제 **1,426,492토큰·32회 파이프라인 호출**을 사용했다. 입력 1,388,615, 출력 37,877이며 캐시 입력 852,608은 입력 합계에 이미 포함된다. 실패·재시도·미측정 호출·예산 중단은 모두 0회다. 계정 사용량 비율이나 실제 청구액을 뜻하지 않는다. 유지보수 대화·Astra 검토 사용량은 이 리서치 수치와 별개다.

## 전체 본문 블라인드 검토

생성 모델·설정 이름·기존 자동 판정을 제거하고 원문·질문·보고서를 별도 Astra 작업에 전달했다. 검토자는 본문 전체와 자동 후보 목록을 대조해 인용구 속 사실도 포함하고, 헤더와 순수 추천은 제외했다. 이는 **단일 모델의 블라인드 판정**이며 사람의 외부 검증이나 독립적인 진실 판정은 아니다. 반복되는 주장도 각 등장 위치를 검사하므로 아래 170개는 서로 독립적인 시험 170건이 아니다.

|---|---|---:|---:|---:|
| 한국어 | 기준 | 27 | 26 | 1 |
| 한국어 | 비평 통합 | 20 | 20 | 0 |

판정은 보고서 해시·문자 위치·인용 ID에 결속해 검사했고, 잘못 연결되거나 판정이 누락된 제출 항목은 없었다. 후보 목록 자체의 완전성을 자동 증명한 것은 아니다. 주요 문제는 산술평균 제한의 확대 해석, 복합문장에 필요한 S1 인용 누락, 자료가 확인해 주지 않는 측정 경계 차이 단정이다. 자동 통과한 영어 비평 통합 보고서에도 세 가지 근거 부족 지적이 있었다. 자동 최종 상태와 본문 검토를 모두 충족한 실행은 없으므로 품질 충족 보고서당 비용 우위를 주장하지 않는다.

첫 검토 자료에는 원문 전체만 넣었기 때문에, 한국어 두 보고서의 '받은 노트가 잘렸다'는 설명을 근거 부족으로 판정했다. 실제 모든 한국어 writer에는 동일한 5,000자 제한과 S2의 잘림 표식이 제공됐음을 확인했다. 모델/설정 이름을 공개하지 않고 이 동일한 입력 맥락을 보완한 뒤 재평가해 지원 판정으로 정정했다. 기존 판정과 재평가 기록은 모두 보존했다. 발췌의 한계와 원문 자체의 불완전성은 구분해야 한다.

## Semantic ON/OFF의 해석 한계

각 실행은 초안부터 독립 생성되어 검사 문장도 서로 다르다. 따라서 미지지 표본 수의 증가를 오류 탐지율 개선으로 해석할 수 없고, precision/recall도 계산하지 않았다. 세부 검사 실행의 미지지 네 표본 중 세 개는 `따라서/를`, `whereas`, `while`이 원자 주장 범위에서 빠져 구조 검사상 낮춰진 사례였다. 나머지 한 개는 뒤의 판단 표식이 표본 분리에서 떨어진 제안 문장이었다. 이 네 개를 새 사실 오류 네 개를 탐지한 것으로 세면 안 된다.

세부 검사 보고서 두 개의 전체 본문 검토에서는 근거 부족 후보가 없었지만, 질문당 한 번인 작은 dev 실험이고 동일 본문으로 ON/OFF를 재판정한 실험도 아니다. 일반 정확도·원본 오픈소스 대비 우위·목표 절감률은 입증하지 않았다.

## 실측 이후 수정과 검증

여섯 실행이 모두 끝난 뒤에만 코드를 바꿨다. 저장된 실측 보고서와 판정은 수정 후 결과로 덮어쓰지 않았다.

- 인용 뒤 `(판단)`/`(judgment)` 표식을 문장에 붙여 유지한다. 여러 공백·탭에서도 표식이 분리되지 않고 같은 줄의 뒤따르는 사실 문장은 계속 검사한다.
- 통합 비평에도 기존 비평처럼 입력 파일을 한 번에 읽도록 안내한다. 한국어 통합 비평 로그에서 여러 번의 탐색·읽기와 입력 75,539토큰이 관찰됐다. 프롬프트 개선의 실제 절감 효과는 재측정하지 않았다.
- 세부 근거 프롬프트에 조사·연결어·부정·수치·연산자를 원자 주장 범위에서 빠뜨리지 않도록 명시한다. 범위 검사를 느슨하게 만들지 않는다.
- 범위 누락 때문에 지원 판정을 확정하지 못했을 때 그 이유를 사용자에게 설명한다. 모델의 지지 설명만 남은 채 미지지로 표시되는 혼란을 줄인다.

추가 유료 리서치 재실행은 하지 않았다. 수정 후 오프라인 회귀 및 Astra 재검수 결과는 TEST-PLAN에 기록한다. 후속 검증이 필요하다면 같은 본문·같은 표본에 대한 ON/OFF 비교와 반복 실험 예산을 별도로 정해야 한다.

검토에서 지적한 다섯 문장은 원본과 분리한 세 개의 `reviewed_report.md`에 수정했다. 해석 범위를 원문 수준으로 좁히고 누락된 인용을 추가했으며, 수정 전후와 원문 해시를 기록했다. 이 편집 수정본은 새 실측이나 새 점수로 집계하지 않는다.
