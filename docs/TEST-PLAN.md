## 토큰 절약 방침 (구독 계정 기준, 2026-09-13)

- 새 실제 실행은 계획표의 것만, lean 프리셋·예산 상한과 함께. 그 밖의 확인은 mock·오프라인으로.
- 원본 비교 채점은 Codex 심판 대신 사람이(또는 Claude 세션이) 읽고 평가한다 → Codex 사용량 0.
- 사용량 한도에 걸리면 도구가 `state.json` 에 `usage_limit` 과 리셋 시각(메시지에 있으면)을 남기고 멈춘다. 리셋 뒤 `hpr resume <id>` 또는 `hpr resume <id> --at "09:00"` 으로 자동 재개.
- 계획표 실행분은 `sh scripts/run-test-plan.sh --at HH:MM` 로 리셋 직후 한 번에 걸어 둔다(Light lean 4회, 예산 70만씩, 합계 최대 280만 입력 토큰).

## 원본(jordan-gibbs/hyperresearch) 기준 비교는 어떻게

- 원본은 Claude Code 전용이라 같은 기계에서 나란히 돌리려면 Claude Code 설치·사용량이 든다(9/26 전에는 가능). 설치는 사용자 결정.
- 대신 원본이 공개한 **예시 보고서**(DRB #67, Full 16단계, Opus 4.7, RACE 58.3)를 고정 비교 대상으로 쓴다. 같은 질문을 우리 도구로 돌려(#1) 나란히 둔다.
- 공식 채점(DRB RACE)은 Gemini/GPT-5.5 API 키가 필요하다. 키 없이 하는 대안: Codex 에게 RACE 4축(포괄성·통찰·지시 준수·가독성) 루브릭으로 두 보고서를 짝지어 채점시킨다. **비공식**이며 편향 가능성을 적는다.
- 공정하지 않은 점: 원본은 학술 출처 80개 이상·2시간, 우리는 lean 12개 출처·30분 안팎. 결과 차이는 "같은 돈으로 무엇을 얻나"의 비교로 읽는다.
